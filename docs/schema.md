# Firestore Schema

FunnyNews uses four Firestore collections. All fields are **flat** — there is no nested `metadata` blob. This lets Firestore create composite indexes on any field combination.

---

## `stories`

**Doc ID:** URL slug — deterministic, human-readable.  
Generated as: `slugify(title, 60 chars) + "-" + base36(urlHash, 6 chars)`

```ts
{
  // ── Identity ──────────────────────────────────────────────
  url:          string          // canonical article URL
  title:        string
  summary:      string | null   // AI-generated deadpan summary
  content:      string | null   // cached article full text
  author:       string | null
  image_url:    string | null

  // ── Source ────────────────────────────────────────────────
  source:       string          // display name, e.g. "The Onion"
  source_type:  "rss" | "reddit" | "hackernews" | "api" | "manual"
  category:     string          // e.g. "satire", "weird", "tech"
  feed_url:     string | null   // RSS: origin feed URL
  rss_guid:     string | null   // RSS: item GUID for dedup
  reddit_id:    string | null   // Reddit: post ID
  reddit_permalink: string | null
  hn_id:        string | null   // HN: Algolia objectID

  // ── AI / scoring ──────────────────────────────────────────
  tags:           string[]      // 3–8 lowercase topic tags
  funny_score:    number        // 1–100 absurdity score
  quality_score:  number        // 0–100 (reserved)
  ai_summary:     boolean       // true if summary was AI-generated
  ai_model:       string | null // "groq/llama-3.3-70b-versatile" | "gemini-2.0-flash"
  ai_version:     number        // prompt version; bump to trigger reprocess
  needs_reprocess: boolean      // true when AI enhancement failed

  // ── Engagement ────────────────────────────────────────────
  upvotes:      number
  downvotes:    number
  view_count:   number

  // ── Status ────────────────────────────────────────────────
  content_status: "ok" | "paywall" | "empty" | "bot_blocked" | "unknown"

  // ── Timestamps ────────────────────────────────────────────
  published_at: string | null   // ISO string from source
  scraped_at:   Timestamp       // server timestamp set on upsert
  created_at:   Timestamp
  updated_at:   Timestamp
}
```

### Recommended composite indexes

| Fields | Use case |
|---|---|
| `category ASC, scraped_at DESC` | Category feed pages |
| `needs_reprocess ASC, scraped_at DESC` | Reprocess queue |
| `source_type ASC, scraped_at DESC` | Source-filtered views |

## `story_relationships`

**Doc ID:** `[slugA, slugB].sort().join("__")` — deterministic, deduped regardless of argument order.

```ts
{
  source_id:         string   // slug of one story
  target_id:         string   // slug of the other
  relationship_type: "similar" | "follow_up" | "related"
  strength:          number   // 0.3–1.0 Jaccard composite score
  created_at:        Timestamp
}
```

Created and updated by the **Relationship Agent** after every scrape run. The graph API reads this collection directly.

---

## `feed_runs`

**Doc ID:** auto-generated by Firestore.

```ts
{
  started_at:     Timestamp
  finished_at:    Timestamp | null
  status:         "running" | "done" | "failed"
  sources_tried:  number
  stories_found:  number
  stories_saved:  number
  stories_failed: number
  ai_enhanced:    number
  errors:         string[]
}
```

One document per scrape cycle. Used for observability — view via `GET /api/scrape/runs`.

## `digests`

**Doc ID:** `YYYY-MM-DD` — one document per calendar day. Re-running the digest on the same day overwrites.

```ts
{
  headline:     string      // first sentence of content (auto-extracted)
  content:      string      // 3-sentence LLM-generated prose
  story_slugs:  string[]    // slugs of the 8 source stories
  top_tags:     string[]    // union of their tags (max 8)
  model:        string      // which LLM generated this
  generated_at: Timestamp
}
```

Read by `GET /api/digest/latest` (backend) and `GET /api/digest` (Next.js proxy). Rendered on the homepage as an amber-bordered `DigestCard`.

---

## Legacy compatibility

Older documents (written before the schema redesign) may have a `metadata: {}` blob containing `feed_category`, `rss_guid`, `reddit_id`, etc. The `toNewsStory()` mapper in both `lib/firebase/firestore-admin.ts` and `backend/src/firebase/firestore-admin.ts` reads flat fields first and falls back to the `metadata` blob for any field that is missing at the top level. New writes always use flat fields.
